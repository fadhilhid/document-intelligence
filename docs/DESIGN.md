# Design Direction

## Product character

DocIntel should feel like a careful tender-review desk: practical, document-led, and accountable. The interface should make evidence and review status easier to inspect than generated summaries.

## Visual choices

- Use warm paper and ink tones with one restrained green action color. This recalls document review without mimicking a PDF viewer or generic AI dashboard.
- Use a strong, readable sans-serif for interface text and a restrained serif only for document-like section headings if it improves hierarchy.
- Prefer crisp separators and compact rows over decorative cards; tender packages and checklists are structured working material.
- Reserve color for status and actions. Pair every status color with a text label and never make color the only signal.
- Keep source references visible alongside checklist content; do not hide citations in a secondary “AI details” panel.

## Interaction rules

- Every extracted statement is a candidate until a person reviews it.
- Make upload, processing, review, conflict, and error states explicit.
- Do not present sample statistics or fabricated requirement data.
- A reviewer should be able to move from a checklist item to the cited document page.
- At narrow widths, reflow the navigation and turn table-like checklist rows into stacked readable records.
- Preserve visible keyboard focus, accessible names, and usable target sizes.
